# 通用三 Agent 核心重构

本轮依据用户 2026-10-18 确认的方向实施；旧 G0–G7 与 R0–R5 是原范围的历史证据，不改写为通用能力证明。保留用户配置和已有修改。

## 目标与边界

- `run --url URL --query 需求` 使用同一条三 Agent 主流程；demo 是被测环境，不决定业务引擎能力。
- Design 通过网页工具观察/探索、识别业务歧义、集中提问并设计场景/检查点/验收。问题由模型判断，不以固定中文短语触发。
- Execution 依据当前观察逐步选动作；以任意资源 ID 和用途请求字符串；新资源受控登记并进入可重跑记录。业务歧义返回 Design，不能自行修改已确认预期。
- Diagnosis 基于实际断言和操作证据提出归因与后续行动；不把模型声明当作测试结果。
- LangGraph 保存业务进度并控制探索、澄清、执行、资源等待、诊断及恢复循环。浏览器/真实资源值由服务持有。
- 工具边界、参数/来源引用、预算、断言执行和资源隔离由程序校验；不在核心固定业务路由、资源名、按钮文本或动作序列。
- 模拟服务独立。支持通用网页表单和导航，不声称覆盖所有网站、验证码挑战或认证方式。

## 阶段门禁

每阶段所有规定检查通过、结果和日志写入 `runtime/development/universal/<本轮目录>/` 后才进入下一阶段。失败记录保留，修复后新增验证记录；不跳过测试或降低标准。

| 阶段 | 实施范围 | 必须保存并通过的验证 |
| --- | --- | --- |
| U0 | 当前源码备份、配置指纹、重新采集基线 | 全部现有离线测试，无跳过；Chromium 启动检查；源码清单和配置指纹 |
| U1 | 通用协议、浏览器工具、字符串资源服务 | 非枚举资源（邮箱/订单号/邀请码）获取与引用；复用/取消/空输入/脱敏；任意命名的计划与断言；真实浏览器在不同页面结构上执行；非法目标/缺失资源拒绝 |
| U2 | 三 Agent 与原生图循环 | 自然需求澄清/明确需求不问/无法回答阻断；先观察后设计；执行中新资源；执行发现业务缺口回设计；证据诊断与受约束恢复；预算终止；图状态和暂停继续；固定模型测试与真实模型测试分开记录 |
| U3 | 统一 URL 入口、导出、独立重跑与报告 | CLI 同一路径；新进程无模型重跑；动态资源进入导出计划；失败/阻断/不一致准确报告；资源值不进入模型输入/计划/导出；配置及旧证据保持不变 |
| U4 | 跨业务验收、清理与文档 | 至少三种不同业务结构通过同一引擎且不修改核心；自然需求真实模型评估，记录全部失败与修复；完整离线回归；用户可自行运行的示例；旧主路径退役并说明历史产物兼容边界 |

## 验收不能偷换的标准

1. 脚本中的模拟回答只证明机制；澄清判断另用真实模型、无提问暗示的需求验证。
2. 模型不能从网站当前结果反推正确业务预期；缺少可靠验收依据时提问或阻断。
3. 同一个业务流程复用会话；独立场景隔离。重跑使用新浏览器并重新请求不可复用资源。
4. 已确认目标不因失败被改写；重新规划产生新版本并保留原证据。可能已提交的副作用不得盲目重复。
5. 新增普通业务资源或更换 URL 不需要修改引擎枚举/校验分支。

## 实施方式

先建立小型 `e2e_agent/core` 核心并逐阶段验证，切换后作为唯一新运行主路径。迁移通用能力，不把旧业务模块整块搬入。旧实现仅服务迁移回归和历史产物兼容，不继续扩展。现有 `.env`、IDE 设置、依赖锁及历史证据保持原样。
