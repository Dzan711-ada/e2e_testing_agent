# 证据审查与诊断

商城 Agent 流程发生执行失败或错误后，会调用独立的审查与诊断角色。可使用既有解释器运行 `main.py diagnose <结构化运行目录>`，对已保存的脱敏记录产生新的诊断版本。普通 `replay` 仍不调用模型。

诊断区分疑似产品问题、Agent 操作问题、环境、需求规则和证据不足。输出引用本轮存在的证据编号，列出反证、不确定项及调查建议。截图记录仅表示掩码图片存在；未提供图像像素时，模型不能声称检查过图片。超时或 AssertionError 本身不证明网站有缺陷。

断言保存原始预期的摘要、实际结果和规则来源；页面保留候选元素及脱敏提示信息。网络只保留有限的请求方法、无认证信息的网址、响应状态与连接失败元信息，不保存认证头、Cookie、请求正文或响应正文。需求覆盖审查直接比较冻结计划与实际断言记录，不能用自然语言“已通过”替代证据。

本地商城还提供独立的只读账号存在／密码匹配布尔证据和登录次数。每次资源填入后核对实际输入与当前资源是否相同；随机资源绑定编号证明注册和登录复用了同一资源，不记录资源值或资源值摘要。这些是事实证据，不是故障类型或分类答案。

每次诊断保存独立目录中的执行快照、证据集、模型调用和结论，原执行状态不变。重跑前归档上一轮日志、JUnit 和检查点产物。阶段 5 不执行任何修复；建议不等于已证明原因或已修复。

缺少预期来源时必须返回规则澄清；证据不足时可返回 unknown 并列出调查事项。不支持把旧的原始 DOM／trace 历史记录直接送给模型，避免泄漏认证内容。

运行时保存已确认的来源目录，诊断核对来源身份与需求摘要；摘要不匹配的旧记录被拒绝，没有保存的来源不能仅凭一个编号视为已确认。诊断使用该次运行冻结的约定，而非从新页面表现补写规则。

验证入口为 `scripts/verify_stage.py --stage 5`。固定角色验证仅证明接口与约束；真实模型分类专项另行记录。评测标签由验证程序持有，故障开关名称及标签不进入诊断输入。固定输入版本与摘要、关键样例、扩展样例和保留样例分别保留，结果不能外推为支持任意网站。

角色协议版本 2 中，设计角色定义来源、检查、依赖和资源；执行角色根据当前页面逐检查点生成动作，程序检查字段用途、资源引用、操作顺序、实际刷新和既有预算。普通导出重跑仍使用已生成的动作，不需要模型。被中断的部分计划保留已确认规则和答案；`resume` 从新会话开始并补齐缺失动作，不能恢复旧验证码或冒充完整脚本。运行时账号使用 acquisition=runtime，确需重复填写时显式声明 reusable=true；一次性资源保持一次性语义。
