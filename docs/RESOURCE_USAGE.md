# 人工资源与独立重跑

在项目目录使用既有解释器运行 `main.py run --shop --headed`。输入测试目标后直接回车发送。需要资源时，主控制台显示类型、用途和取消方法；输入一行后回车，输入 `:cancel` 取消，不需要 `/send`。模拟商城不会向真实手机发送短信；公开虚构模式会在本地控制台显示当次模拟验证码。

手机号与验证码分开请求。每条业务链沿用当前浏览器会话，发码、登录各一次；加购不再次索取验证码。验证码只能用于当前运行、手机号与挑战，过期或已使用后不能复用。人工等待独立计时，不消耗一般浏览器操作时限；人工等待也有截止时间。EOF、取消与无交互渠道得到明确的 blocked 或 cancelled，不能当作通过。

独立重跑使用 `main.py replay <运行目录>`。资源请求通过经过认证的本机回环代理返回主控制台；Pytest 子进程不读取标准输入。新一轮重新建立浏览器与命名空间，需要新的验证码。导出工程还包含 `run_with_resources.py`，在约定依赖下直接运行它即可使用同样的主控制台机制，不需要模型或原项目。仅本地虚构示例的自动演示可显式加 `--scripted-fixture`；直接运行 Pytest 而未提供资源代理时，缺失资源会阻塞。

中断后使用 `main.py resume <运行目录>` 从已保存的计划建立新一轮。记录会关联旧运行，但不会恢复旧浏览器句柄、旧验证码或旧登录结论。进程仍存活的正常等待则直接继续，不重做发码动作。退出时关闭本轮浏览器、资源代理和临时商城。

账号、密码、手机号与验证码通过资源引用进入动作和导出脚本。明文仅在当前资源生命周期内传给浏览器；模型输入、报告、JSON、URL 与异常按资源注册表脱敏。截图掩盖表单与身份信息，不保存原始 DOM、网络载荷或完整 trace。API 密钥继续来自原环境配置。普通回放不调用模型。

真实私密输入使用支持隐藏输入的终端。PyCharm 的无 TTY 控制台可用于公开虚构模拟输入；无法隐藏真实私密输入时会明确阻塞，避免回显。图形或滑块验证尚不支持自动处理。

阶段验收命令：`scripts/verify_stage.py --stage 4 --manual-evidence <manual-evidence.json>`。实际人工验收由 `scripts/manual_sms.py --output <新证据目录>` 在有界面浏览器中完成首次执行及独立重跑。脚本提供者的通过记录不能替代人工验收。`verify_resources.py --quick` 只是诊断模式，不满足等待超过 worker_timeout 的门槛。
