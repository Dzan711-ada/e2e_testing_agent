# G7 使用与交付说明

运行前使用项目现有解释器和配置；完整命令见 README 的“G7 交付入口”。本阶段不新增依赖，不覆盖 `.env`、IDE 配置或旧运行。

## 观察一个完整流程

运行 `main.py run --shop --headed --query "注册新账号后登录，添加一本 Agent Handbook，检查数量为 1 且刷新后保留"`。程序观察页面、设计检查点、生成动作批次、复用同链会话并导出，随后在新浏览器独立重跑。终端给出 Markdown 和 HTML 报告位置。需求澄清在父控制台回答；模拟短信需每轮新验证码。

## 选定公开站

运行 `main.py run --site practice-login --headed`。范围固定为正确凭据登录与错误密码拒绝，两场景独立上下文。该入口没有任意 URL／注册／购物车／SMS 扩展。公开站来源为 https://the-internet.herokuapp.com/login ，程序依赖公开演示资源与冻结的 URL／控件断言；不根据页面当前表现猜业务规则。网络错误与本地协议镜像分开，只有真实公网首次和独立重跑成功才声称基础兼容。

## 结果、修复与重跑

`report.md / report.html` 展示各场景和检查点、验收来源与覆盖、首次／重跑差异、人工证据、诊断和修复。`failed`、`blocked`、`cancelled` 均保留；`repaired=true` 不擦除原始失败。无人工证据时不把自动 provider 声称为真人。

`main.py replay <实际运行目录>` 无模型重跑有效脚本，保留初次报告并另记本次重跑。`main.py resume <实际运行目录>` 从已保存计划安全起点重新执行，缺失动作批次才规划；不恢复原浏览器或旧验证码。新父图运行及缺失批次续规划生成统一报告；完整已保存脚本的安全重启沿用 `restart-result.json`，原报告仍保留。独立导出用 `python run_with_resources.py` 在父控制台输入资源，或预置 `E2E_RESOURCE_USERNAME`、`E2E_RESOURCE_PASSWORD`、`E2E_RESOURCE_WRONG_PASSWORD` 后运行 pytest；不把私密值写入脚本。

## 故障演示与对照

README 提供过时定位及正确密码被拒绝的固定角色演示：前者可在原约束内恢复，后者保留疑似产品失败。它是程序控制验证，不冒称真实模型能力；G7 另有真实模型专项。

`verify_comparison.py` 固定输入，三案例×三可比臂×两次重复：仅规划执行、加入诊断、加入修复。全部 18 行都保留，包括失败、拒绝和差异。旧基线不能执行同一商城协议，表中对应项为不可比较，仅列本次 G6 原兼容流程作为独立参考。故障由评测环境持有，不发给模型；首次故障与健康独立重跑的不一致会明确记录。

## 验收边界

`scripts/verify_stage.py --stage 7` 绑定源码快照、全部前序身份、固定输入、当前模型配置及保护配置。自动通过仍是 waiting_user；新人工首次／独立重跑通过且摘要再次核验后才 passed。所有失败记录保留。没有 G8；Web 管理界面、多模态、复杂认证和跨进程原位恢复不属于本次交付。
